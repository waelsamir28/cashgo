## ✅ ينفع؟ نعم — والطريقة سهلة جداً (منفّذة بالفعل في الكود)

البرنامج دلوقتي فيه **3 طبقات**:

| الطبقة | الوظيفة | قابلة للتغيير من العميل؟ |
|---|---|---|
| **شاشة البداية** | دخول بالاسم فقط (الافتراضي «المدير») + زر دخول + زر خروج + رسالة ترحيب عائمة + دعاية الدعم | الاسم فقط |
| **الفترة التجريبية** | **10 أيام** من أول تشغيل + **25 صنفاً فقط** + شريط تنبيه بعدد الأيام | ❌ محسوبة تلقائياً |
| **التفعيل** | **كلمة سر يعرفها أنت فقط** تُدخلها أنت (أو توصلها للعميل بعد الدفع) | ❌ التحقق في السيرفر فقط |

## 🔑 كلمة سر التفعيل (الافتراضية)

```
WaelGamal@2026
```

- كلمة السر **غير مكتوبة كنص صريح داخل كود البرنامج**: المخزّن هو بصمة `SHA256` فقط في
  `src/lib/license-config.ts`، والتحقق بيحصل في `/api/license` على السيرفر.
- **تغييرها أسهل حاجة**: اضبط متغير البيئة في ملف `.env` قبل بناء الـ EXE:
  ```env
  ALGAMAL_ACTIVATION_PASSWORD=أي-كلمة-تحبها
  ```
  المتغير له الأولوية، فلا تحتاج تحسب بصمة جديدة ولا تلمس الكود.
- لو حابب تغيّر البصمة نفسها:
  ```bash
  node -e "console.log(require('crypto').createHash('sha256').update('الكلمه_الجديده').digest('hex'))"
  ```
  ثم ضع الناتج في `secretHash` بنفس الملف.

## ⚙️ تغيير مدة التجربة أو عدد الأصناف
افتح `src/lib/license-config.ts` وعدّل سطرين فقط:
```ts
trialDays: 10,            // ← مثلاً 15 أو 30
trialProductLimit: 25,    // ← مثلاً 10 أو 50
```
ثم `npm run build` وابنِ الـ EXE من جديد. (في قاعدة البيانات فيه دالة `setTrialPolicy`
جاهزة لو حببت تضبطها لنسخة معينة عبر API بكلمة السر.)

## 🧾 سيناريو الاستخدام مع العميل (خطواتك أنت)
1. ابنِ الـ EXE مرة واحدة: `build-exe.bat` (أو الأوامر في `README-EXE.md`).
2. ادّي الملف للعميل — أول ما يفتحه: **شاشة البداية** تظهر، يسجّل دخوله بالاسم، ويبدأ يجرب.
3. البرنامج يسجّل تلقائياً في `algamal.db`: `installId` (كود الجهاز) + تاريخ أول تشغيل.
4. كل يوم يظهر له شريط: «نسخة تجريبية — متبقي X يوم ... زر تفعيل».
5. بعد 10 أيام → **شاشة حجب كاملة** فيها كود الجهاز + زر **«اطلب كلمة السر واتساب»** (يفتح محادثة جاهزة ليك بالكود).
6. لما يدفع: تبعته كلمة السر (أو تدخلها أنت عنده)، يكتبها ويضغط «تفعيل» → **كل الأصناف + بلا حد زمني + شريط تجريبي يختفي** فوراً.

> 💡 الأقوى والأأسهل لك: خلّي العميل يبعتلك **كود الجهاز** على واتساب، وابعته كلمة السر بعد الدفع.
> كده أنت المتحكم الوحيد، والكلمة ما بتتخزّنش في أي ملف يوصل للعميل.

## 🔒 إيه اللي العميل يقدر يغيّره وإيه اللي ما يقدرش
| يقدر يغيّر | ما يقدرش يغيّره |
|---|---|
| اسم المحل، رقم هاتف المحل (يظهر في **الفواتير فقط**)، العنوان، العملة، الضريبة | **اسم م. وائل الجمال** ورقم **01222355769** في كل شاشات الدعم |
| أرقام الفواتير، أرقام هواتف العملاء، الأصناف، الأسعار، الثيمات، تصميم الفواتير، التخصيص | كلمة سر التفعيل، مدة التجربة، حد الأصناف، كود الجهاز |
| بياناته كلها في النسخة الاحتياطية | بيانات الدعم (مصدر واحد `src/lib/support.ts`) |

> رقم الدعم له **مصدر واحد** `src/lib/support.ts`، وأي شاشة دعم (الرئيسية، البداية، الدعم، الإعدادات، عن البرنامج، القائمة الجانبية) بتقرأ منه مباشرة — فحتى لو العميل غيّر `settings.phone`، رقمك ما بيتغيّرش.

## 🗄️ قاعدة البيانات
- جدول جديد `license` في `src/db/schema-sql.json`:
  `installId`, `installedAt`, `activated`, `activatedAt`, `trialDays`, `trialProductLimit`.
- الملف في `%APPDATA%\algamal-desktop\algamal.db` → **بيستمر بعد التحديثات**، فما ينفعش العميل يمسحه ويبدأ تجربة جديدة بسهولة
  (ولو مسحه، يبدأ من جديد — وده مقبول عملياً؛ ولو حابب تمنعه خالص، ابعتلي كود الجهاز وأربطه بسيرفر تفعيل أونلاين).
- الوحدة `database.js` (IPC) بتستخدم نفس ملف المخطط، فالجداول متزامنة بين العملية الرئيسية وخادم Next.js.

## 🧠 ملاحظة أمان صريحة
أي حماية داخل ملف EXE على جهاز العميل ممكن فنياً التحايل عليها بواسطة شخص تقني جداً
(تعديل ساعة النظام، حذف ملف الـ db، تعديل الكود). النظام الحالي **ممتاز كـ «اتفاق تجاري + تتبع + سهولة»**
وهو الأنسب لبرنامج محلي بدون إنترنت. لو حابب حماية أقصى لاحقاً: نربط التفعيل بسيرفر أونلاين
(البرنامج يتحقق مرة عند الفتح + كود الجهاز + توقيع رقمي)، وده بنقدر نضيفه بسهولة فوق النظام الحالي.
